### D5 — TTL-only fix can consume the wrong `allow_once` row (two grants, same args)

The plan's `expires_at > now` bullet (`105:95`) does not address row identity.
**Patch:** thread the `approval_id` from the committed decision through `apply_committed_decision` → `resume_and_execute` → `execute_approved`/`verify_tool_grant`; query by `approval_id` (and `args_sha256`) rather than any matching row. If identity cannot be threaded this round, select `AND (expires_at IS NULL OR expires_at > ?now)` and document that the newest valid row is chosen, but identity is the correct fix.
**RED:** new test in `approval.rs`: two `request` rows for the same `(run, ToolId::FileWrite, args)`; set first `expires_at` past (decide AllowOnce then time past), decide second AllowOnce valid; `verify_grant` with the second's approval id must succeed and consume the second. Current code consumes the first (or a naive TTL check refuses). `cargo test -p hiverouter-tools approval::tests::two_identical_grants_bind_the_right_row -- --exact`.

## 4. Ordering hazards

1. **R1/R2 inversion (D1).** The docs/analysis commit is R1's output, yet R2's two scripts are edited in the same dirty tree. Any strict gate now sees a dirty tree; if the edits are reverted, the checker goes back to 17/19 and R2 evidence disappears. Fix the order: commit the two QA files as an explicit R2 commit after recording the R1 baseline, or revert and redo R2.
2. **Cross-crate approval API change has no buildable intermediate (D4/D5/D6).** `verify_grant` lives in `hiverouter-tools`; call sites in `hiverouter-tools` tests, `side_effects.rs`, `tools_bridge.rs` (H1) and `execution.rs` (Lead). Changing its signature first breaks the workspace until the Lead's core call-site patch lands. Use a `#[deprecated]` wrapper or an `Option<GrantIdentity>` default so the tree compiles at every round; do not bundle R3-R5's "full focused suite" exit unless each commit compiles.
3. **Daemon/security split (D9).** WP-SEC-1's daemon item and WP-SEC-2's `execution.rs`/`run_state.rs`/`approval_wait.rs` items are Lead-owned but scheduled in H1 rounds. Either the Lead executes those files in the same rounds (the plan's "one writer per file" forbids H1) or the rounds slip. The plan should say which.
4. **UI fix collision.** `App.tsx`/`store.ts` are H2's `web/**`; the plan gives `App.tsx`, `store.ts` to WP-UI-1 (H2 is `impl-ui-install`), but the header/chat and tabs fixes require H2 edits in the same files as `AgentsPanel`/`LibraryPanel`. No two writers, but there is no serialization of `store.ts` vs `App.tsx` across UI-1/UI-2; assign them to H2 and keep the Lead out of `web/**` (or serialize by round).
5. **v24** remains the largest cross-WP ordering risk (fact-check F-11/F-12); it is outside this first-fix audit, but R6's `WP-SCHEMA-1` still precedes WP-GOV-1/WP-STATE-1's shared columns with no frozen inventory.
