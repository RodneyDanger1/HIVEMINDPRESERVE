## 0. Scope and non-claims

- **PAPER** Scaffold evolution (DGM/Hyperagents) improves agents *without weight updates*; the sub-4 GB student still requires gradients (§III.1, §III.5.1).
- **PAPER** Fitness must be vector-valued, Pareto/quality-diversity selected, never a weighted sum; correctness gates other objectives (§III.2.4).
- **PAPER** Test-based fitness is gameable; evaluators must be hidden and held out; hacks spread through crossover, so lineage tracking + quarantine are required (§III.2.5).
- **CODE** HiveMind has **no** training path, no optimizers, no weights, no gradient access: the provider crate is an HTTP client (`backend/crates/hiverouter-provider/src/client.rs:1-936`) and the only "model" surface is DTOs (`.../dto.rs`). **This audit does not claim HiveMind trains, distills, or gradients any model.** Distillation is out of architectural reach, not merely unbuilt.
- **CODE** Grep over `backend/crates/**/*.rs` for `archive|population|fitness|held-out|oracle|critic|distill|quantiz|gguf|pareto|novelty` returns **no functional hits** — only the words "variant"/"archive" inside comments about Rust enums and zip assets. Mechanism set is essentially absent.

## 2. Top-3 ranked proposals

Ranked by (benefit to real current risk) ÷ (cost × security risk). All are additive, local, no-mock, and gated.

**P1 — Sealed acceptance set (mechanism 4).** Benefit: closes the largest honest gap — completion is currently self-reported; an independent held-out check is the paper's best-evidenced control (§III.2.5) and the only one that raises trust in every run. Cost: ~1 module + 1 operator route + 2 tests, no new dependency. Security risk: **low** — read-only checks, hash-pinned inputs, execution through the existing confined executor; the new attack surface is the operator route, which reuses the approval pattern. **Worth doing now**: yes. It adds value without inventing a fitness function or a training path.

**P2 — Diff-class guard for tests/CI/logging (mechanism 5).** Benefit: converts the paper's documented failure mode into a mechanical approval gate, reusing `safety_class = critical` and the nonce-bound approval already tested (`remote.rs:1649`). Cost: ~1 predicate + tests. Security risk: **low**, and it *reduces* risk (forces human review exactly where reward hacking lives). **Worth doing now**: yes, immediately after P1 — it is the cheapest high-signal control in the repo.

**P3 — StatePack v1 export/import (mechanism 6).** Benefit: reproducible handoff and a clean operator-facing artifact; builds directly on proven snapshot/migration code. Cost: ~1 module + 1 route + round-trip/corruption tests. Security risk: **medium** — an import path is a parser over attacker-influenced JSON and can corrupt the authoritative graph if validation is skipped; must validate fully and stage before apply. **Worth doing now**: conditionally. Do it only after P1/P2, and only with the corrupt-pack refusal test written first.

**Explicitly not worth doing now:** a scored archive/population (P3 in the paper's terms) — no ground truth exists, so any score is fabricated, violating the no-mock rule; scaffold mutation search — the caps (`caps.rs:9-18`) and single planning call make variants cheap but *unscorable*; sub-4 GB distillation — no weights, no gradients, no dataset, and it would be dishonest to imply HiveMind can do it.

## 4. One-line summary

HiveMind today is a **governed topology runtime** (fixed caps, validated DAGs, versioned snapshots, append-only ledger, approval-gated side effects) — it is honest about not evolving scaffolds and not training models; the highest-value paper mechanisms it can adopt *now* are hidden acceptance checks, a diff-class guard, and a validated state pack, in that order.
